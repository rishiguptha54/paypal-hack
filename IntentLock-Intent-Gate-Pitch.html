01 / The control gap

A recommendation isn't authorization.

The user's request can be clear while the final order quietly drifts.

User's confirmed request

"Buy two ergonomic chairs for the team. Keep the total under $400, use an approved seller, and do not add a subscription."

Illustrative demo scenario; not a market statistic.

!
Price changesThe selected quantity pushes the total above the user's limit.
!
Seller changesA product page or redirect substitutes a seller the user did not approve.
!
Terms changeA recurring plan, add-on, or different quantity appears at checkout.
IntentLock's job is not to make the agent smarter. It is to re-check what will actually be paid.
Product thesis: authorization should bind to the transaction, not only the conversation.02 / 09

02 / The product

IntentLock turns intent into a purchase mandate.

The user confirms structured rules. Deterministic code checks them against a server-owned order snapshot.

01 / INTERPRET

AI proposes constraints

Item, quantity, maximum total, allowed seller, recurring terms, expiry.

02 / CONFIRM

User fixes the mandate

Ambiguity asks a question. No missing permission is silently invented.

03 / VERIFY

Code checks the final order

Recalculate from trusted product and order data; unknown fields fail closed.

04 / AUTHORIZE

PayPal completes checkout

Buyer approves in PayPal. Backend re-checks policy before capture.

What is meaningfully different?

A buyer-side checkpoint that binds a confirmed mandate to a specific order and invalidates approval when protected fields change.

What we are not claiming

Not a new payment rail, not a replacement for PayPal Agent Ready or commerce protocols, and not a claim that no comparable policy product exists.

Novelty is a product hypothesis to test, not an absolute claim.03 / 09

03 / End-to-end flow

The policy check sits directly before capture.

PayPal approval

Re-check + capture

05 / Architecture

AI proposes. Backend owns the authorization boundary.

Every external response is normalized; every payment action references an approved, persisted purchase.

AI + product data

  • Extract structured mandate
  • Channel3 search adapter
  • Untrusted text stays data
>

IntentLock policy service

  • Runtime schema validation
  • Deterministic rule evaluation
  • Persist snapshot + approval
>

PayPal Sandbox

  • Orders API create
  • Buyer checkout approval
  • Server re-check + capture

Stack

React + TypeScript / Node + Express / Zod / PostgreSQL / PayPal Orders v2 / AG Grid Community.

Hard boundary

No model-controlled capture; no client-supplied total trusted; no public secrets; idempotent payment operations; verified status only from PayPal.

External checkout limitation: Channel3 documents product search and lookup; its programmatic checkout is marked "Coming soon" with early access by request. The demo uses PayPal Sandbox checkout for the app's own test order.
Unknown seller, price, recurrence, or order mapping means review/block, never implicit approval.06 / 09

07 / Build and prove

De-risk checkout first; measure the guardrail, not the hype.

A narrow working system is more persuasive than a broad mockup.

Gate 0

PayPal vertical slice. Create, buyer-approve, capture, and reconcile one Sandbox order. Confirm the exact state flow before building the agent.

Gate 1

Policy core. Schema, clarification, deterministic evaluation, approval binding, mutation/retry tests.

Gate 2

Real discovery + ledger. Channel3 access check; integrate search if available; otherwise label fixtures. Add AG Grid and deploy.

Gate 3

Judge-ready demo. Re-run tests from clean setup; record the real flow; include source links and test credentials securely.
